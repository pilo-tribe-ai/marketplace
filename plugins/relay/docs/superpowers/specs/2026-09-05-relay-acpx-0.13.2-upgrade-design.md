# acpx 0.13.2: floor, wide permissions, structured envelope

Date: 2026-09-05
Status: implemented in relay 4.51.0 (commit a131486)
Target version: relay 4.51.0
Supersedes: the `ACPX_CODEX_AGENT_OVERRIDE` workaround (PR #52, relay 4.6.1)

## The problem

Relay runs every out-of-session leaf through the `acpx` CLI. The latest acpx is
**0.13.2** (published 2026-08-28). Relay states a floor of 0.12.0 and this machine runs
0.12.0. Four releases sit between them, and they change things relay has worked around
by hand.

Six facts in the code and in acpx shape this design:

1. **The floor is prose, and the prose disagrees with itself.** No script checks the acpx
   version. `skills/setting-up-relay/SKILL.md:21,25` and `skills/setting-up-engines/SKILL.md:23`
   say `>= 0.12.0`. `skills/check-readiness/SKILL.md:34,38` says `>= 0.7.0`.
   `flows/package.json:7` says `>=0.7.0` and `flows/package-lock.json` resolves 0.10.0.
   `tests/unit/skill-structure/test_flows.py:47,63` locks those stale values in.

2. **The codex `--agent` override is dead weight.** acpx 0.12.0 pinned its codex adapter
   to `@agentclientprotocol/codex-acp@^0.0.44`, which was broken. Relay replaced the
   `codex` positional with `--agent "npx -y @agentclientprotocol/codex-acp@latest"` on
   every one-shot path (`acpx-dispatch.sh:110-126,462-467,735-741`). acpx **0.12.1**
   moved the pin to `^1.1.5`, which resolves to codex-acp 1.10.0 — the same adapter the
   override fetches. Live proof on 0.13.2: `acpx codex exec "Reply with exactly: OK"` with no
   override returned `OK`, exit 0. The override also blocked two things: the codex
   multi-turn driver could not use it (`--agent` drops the positional and mislabels the
   session `claude`), and codex sessions could not set effort through session config.

3. **Three roles run with writes silently denied.** `bindings/presets.yaml` binds
   `code-reviewer`, `doc-reference-reviewer`, and `ui-code-evaluator` to
   `permissions: approve-reads`. The dispatch only ever emits `--approve-all`
   (`acpx-dispatch.sh:733`, `claude-session-driver.sh:76`, `opencode-session-driver.sh:89`).
   acpx's default mode is `--approve-reads`, and with no TTY its non-interactive fallback
   is `deny` (0.13.2 bundle: `nonInteractivePermissions ?? "deny"`). So those three
   roles get every write request denied, and nothing reports it.

4. **Codex effort rides an env hack.** codex-acp 1.10.0 advertises `model` and
   `reasoning_effort` as separate session config options (live `session/new` response,
   `configOptions[]`). Relay still passes effort as `CODEX_CONFIG='{"model_reasoning_effort":…}'`
   on every codex path (`acpx-dispatch.sh:396-403,728,582`; `codex-session-driver.sh:16-24`)
   because the session driver could not run `set` while the `--agent` override was in
   force. On `exec` there is no `set`, and acpx still rejects bracketed ids
   (`--model 'gpt-5.6-luna[low]'` → `RUNTIME Cannot apply --model … did not advertise that
   model`, live on 0.13.2), so `CODEX_CONFIG` must stay on the one-shot path.

5. **Reconnects used to drift silently.** acpx 0.13.1 and 0.13.2 replay the saved model
   and config options after a reconnect and raise
   `Failed to replay saved session {model|config option|mode} …` when the replay fails
   instead of running on defaults. `delegate-and-watch` runs one session across many
   turns and has no bucket for that error (`skills/delegate-and-watch/SKILL.md:113-119`).

6. **The envelope is scraped from `--format quiet` stdout.** Every path captures the
   final text and greps it for `^KEY=VALUE$`, the terminal token, and the first-line
   sentinels `^BLOCKED:` / `^NEEDS_DECISION:` (`acpx-dispatch.sh:504-520,770-790`;
   `codex-session-driver.sh:33-41,86-103`). The recorded watch item is that quiet output
   can glue chunks and corrupt an envelope line. `--format json --json-strict` emits the
   raw ACP stream: each `session/update` with `sessionUpdate: "agent_message_chunk"`
   carries `messageId`, `content.text`, and `_meta`. Live samples on 0.13.2: codex chunks
   carry `_meta.codex.phase: "final_answer"`; claude chunks carry `_meta: null` and split
   mid-token (`"ST"` then `"ATUS=ok\nROLE_DONE"`), which concatenation rebuilds exactly.

## The design

One PR. Six changes, each with one owner file, all behind one floor.

### 1. One floor, one script

New `scripts/acpx-floor.sh`. It holds one constant:

```bash
RELAY_ACPX_MIN=0.13.2
```

It defines `relay_acpx_floor_check`, which runs `acpx --version`, compares semver with
`sort -V`, and on success prints `RELAY_ACPX_VERSION=<version>`. On failure it prints one
line to stderr and returns 1:

```
[relay] error: acpx <found> is below the floor <min>. Run: npm install -g acpx@latest
```

When acpx is absent the line reads `acpx is not on PATH` with the same remedy.

Callers:

- `scripts/l3-preflight.sh`: in every command branch, directly after
  `source "$HERE/parse-engine-agent.sh"`, add
  `[ "$RELAY_ENGINE" = acpx ] && { source "$HERE/acpx-floor.sh"; relay_acpx_floor_check || exit 1; }`.
  The `in-session`, `bg-sessions`, and `session-tree` engines never call acpx, so they do
  not pay the check.
- `skills/setting-up-relay/SKILL.md` Step 0.1, `skills/setting-up-engines/SKILL.md` Step 0,
  and `skills/check-readiness/SKILL.md` step 2 replace their inline `acpx --version` +
  number with `bash "$CLAUDE_PLUGIN_ROOT/scripts/acpx-floor.sh"`. The prose keeps the
  `acpx flow --help` probe.
- `flows/package.json` → `"acpx": ">=0.13.2"`; `flows/package-lock.json` regenerated
  with `npm install --package-lock-only`; `test_flows.py:47,63` assert `>=0.13.2` and
  `(0, 13)`.
- `scripts/bench-dispatch-cost.sh:32` doc line → 0.13.2.

`setting-up-engines` keeps its 0.12.0 paragraph as history and adds one paragraph on why
0.13.2: adapter pins refreshed (0.12.1), reconnect replay with reported failure (0.13.1,
0.13.2), and structured JSON events with `messageId` and `_meta` (0.13.1).

### 2. The wide permission policy

New `bindings/acpx-policy.json`:

```json
{ "defaultAction": "approve" }
```

`defaultAction` accepts `approve | deny | escalate` (0.13.2 bundle validator). Every acpx
turn relay runs now passes both:

```
--approve-all --permission-policy <abs path to bindings/acpx-policy.json>
```

`--approve-all` answers every ACP permission request. The policy file sets the same answer
for the per-tool rule engine, so a future acpx that consults the policy before the mode
gives the same result. Together they are the widest grant acpx exposes.

For codex the adapter has its own sandbox. The session driver adds
`acpx codex set mode agent-full-access -s <session>` after `set model`, soft-degrade like
the other `set` calls. The one-shot `exec` path has no `set`, so `build_codex_config`
adds the codex-cli keys to the JSON it already builds:

```json
{ "model_reasoning_effort": "<e>", "approval_policy": "never", "sandbox_mode": "danger-full-access" }
```

Call sites:

- `acpx-dispatch.sh`: the two fast-path `FP_CMD` arrays (`:482,497`) and the generic
  `CHILD_CMD` (`:733`). The `[ "$PERMISSIONS" = "approve-all" ]` gate goes; the flags are
  unconditional. `POLICY_FILE="${SCRIPT_DIR}/../../bindings/acpx-policy.json"` resolved
  once near the top.
- The three drivers: `approval_flags` becomes unconditional
  (`claude-session-driver.sh:74-76`, `opencode-session-driver.sh:87-89`), and
  `codex-session-driver.sh:75` gains the policy flag. The path arrives as `ACPX_POLICY_FILE`,
  a new sidecar var written next to `ACPX_PERMISSIONS` (`acpx-dispatch.sh:561-578,656-674`)
  so a watcher re-invocation carries it. The driver falls back to
  `${SCRIPT_DIR}/../../bindings/acpx-policy.json` when the var is empty.
- `bindings/presets.yaml:95-98`: the comment now says `permissions` records the role's
  intent and nothing reads it. The 24 role entries stay as they are.
- `skills/dispatching-acpx-agents/SKILL.md:39`: the sentence
  "`--approve-all` is gated on `permissions: approve-all` exactly" becomes "every acpx
  turn passes `--approve-all --permission-policy bindings/acpx-policy.json`; read-only is
  enforced by the role body, not by the substrate".

### 3. Delete the codex override

Remove from `acpx-dispatch.sh`: the header comment and default (`:110-126`), the
`CODEX_ENGINE_ARGS` branch (`:462-467`), and the `--agent` branch in the generic loop
(`:735-741`). Both paths pass the `codex` positional. Remove the section
"Codex registry override" from `skills/dispatching-acpx-agents/SKILL.md:82-94`. One
replacement sentence in the dispatch header:

> acpx >= 0.12.1 pins `@agentclientprotocol/codex-acp@^1.1.5`. The `--agent` override
> that relay 4.6.1 added for the broken `^0.0.44` pin is gone. See
> `docs/superpowers/specs/2026-09-05-relay-acpx-0.13.2-upgrade-design.md`.

### 4. Codex effort through session config

`codex-session-driver.sh` gains the same settle block the other two drivers have
(`claude-session-driver.sh:58-71`), with the codex key names:

```bash
acpx --cwd "$ACPX_CWD" codex set model "$ACPX_MODEL" -s "$ACPX_SESSION_NAME"
acpx --cwd "$ACPX_CWD" codex set reasoning_effort "$ACPX_EFFORT" -s "$ACPX_SESSION_NAME"
acpx --cwd "$ACPX_CWD" codex set mode agent-full-access -s "$ACPX_SESSION_NAME"
```

Each call soft-degrades on rc≠0 with a `[warn]` log line, as today. The turn call drops
`--model` (the session record holds it). `ACPX_EFFORT` joins the codex sidecar
(`acpx-dispatch.sh:561-578`) and the driver env block. The driver no longer needs
`CODEX_CONFIG`; the sidecar keeps writing it for one release so an in-flight watcher on
the old contract still sources cleanly, and the dispatch header marks it for removal.

The one-shot `exec` paths keep `CODEX_CONFIG` (fact 4). `build_codex_config` is the one
place that builds it.

### 5. The watcher learns about replay failure

`skills/delegate-and-watch/SKILL.md:113-119` gains one row:

| bucket | condition |
|--------|-----------|
| `errored` | … OR the turn text carries `ERRORED_REASON=config_replay_failed` |

The envelope script (section 6) is the one place that detects it: when any JSON line in
the turn stream contains the substring `Failed to replay saved session`, the script emits
`ERRORED_REASON=config_replay_failed` as the first line of its output. The drivers already
map a non-zero rc with envelope lines present to `ROLE_RESULT=ERRORED`
(`codex-session-driver.sh:105-110`); they now also pass through that reason line. The
watcher routes to `errored`, never to `not-done`, so the session is not re-dispatched on a
model it did not ask for.

### 6. Structured envelope capture

New `skills/dispatching-acpx-agents/acpx-envelope.sh`. Contract: NDJSON on stdin, the
final assistant text on stdout. Rules, applied with `jq`:

1. Skip any line that is not JSON (defensive; `--json-strict` should leave none).
2. Keep `session/update` events whose `params.update.sessionUpdate` is
   `agent_message_chunk` and whose `content.type` is `text`.
3. When `_meta.codex.phase` is present, keep only chunks whose phase is `final_answer`.
   When `_meta` is null or has no `codex` key (claude, opencode), keep every chunk.
4. Group chunks by `messageId` in stream order. Concatenate each group's `content.text`
   with no separator. The output is the text of the **last** `messageId`, which matches
   what `--format quiet` prints today.
5. Before step 4, if any line contains `Failed to replay saved session`, print
   `ERRORED_REASON=config_replay_failed` first (section 5).

Call sites move from `--format quiet` to `--format json --json-strict` and pipe the raw
stream through the script:

- Fast path: `FP_CMD` (`acpx-dispatch.sh:482,497`) writes NDJSON to `$tmp_out.ndjson`;
  `acpx-envelope.sh < "$tmp_out.ndjson" > "$tmp_out"`. Everything from `:504` on reads
  `$tmp_out` unchanged.
- Generic loop: `"${CHILD_CMD[@]}" > "$STDOUT_FILE.ndjson"` then the same conversion
  into `$STDOUT_FILE`. The token grep at `:770-790` is unchanged.
- Drivers: `final_reply=$(acpx --format json --json-strict … 2>&1 | "$SCRIPT_DIR/acpx-envelope.sh")`.
  The raw stream is also written to `${LOG_DIR}/${ACPX_SESSION_NAME}.turn.ndjson` for
  forensics; `turn.log` keeps the extracted text as today, so the watcher's reader does
  not change.

The `2>&1` stays: `--json-strict` silences non-JSON stderr, and rule 1 drops anything
that still gets through. The frozen capture regex, the sentinels, and the terminal token
are untouched — only the source of the text changes.

## Tests

All under `tests/unit/skill-structure/`, pytest, driven with the fake-acpx pattern the
suite already uses.

- **Floor.** A fake `acpx` on PATH that prints `0.12.0` makes `acpx-floor.sh` exit 1 with
  the error line; `0.13.2` and `0.14.0` pass and print `RELAY_ACPX_VERSION=`; absent
  `acpx` fails with the not-on-PATH line. `l3-preflight.sh implement --engine acpx` fails
  on the fake 0.12.0; `--engine in-session` does not call it.
- **No stale numbers.** A guard scans `scripts/`, `skills/`, `flows/package.json`,
  `README.md`, and `docs/*.md` (not `docs/superpowers/`) for `0\.7\.0`, `0\.12\.0` as a
  floor, and `--agent` in any acpx command line, and fails on a hit.
- **Policy flags.** `ACPX_PRINT_CMD_ONLY=1` for the fast path, the generic loop, and each
  driver shows `--approve-all` and `--permission-policy <path>` on every acpx turn, and
  the path resolves to an existing file. No command line contains `--agent`.
- **Codex settle.** The codex driver's command log shows `set model`, then
  `set reasoning_effort`, then `set mode agent-full-access`, then a turn with no `--model`.
  `build_codex_config low` returns the three-key JSON.
- **Envelope.** `acpx-envelope.sh` on the codex fixture prints `STATUS=ok\nsecond line\nROLE_DONE`;
  on the claude fixture prints `STATUS=ok\nROLE_DONE`; on the glued-chunk fixture (a
  line split across three chunks and a `commentary`-phase chunk) prints only the
  `final_answer` text rebuilt exactly; on the replay-failure fixture prints
  `ERRORED_REASON=config_replay_failed` first; on a non-JSON line it prints nothing for
  that line and does not exit non-zero.
- **Watcher.** The existing classifier test gains the `config_replay_failed` case and
  asserts the bucket is `errored`, not `not-done`.
- **Sidecar.** Both sidecar writers emit `ACPX_POLICY_FILE`; the codex sidecar emits
  `ACPX_EFFORT`.

## Live proof before merge

Run on acpx 0.13.2, recorded in the PR body:

1. `acpx-dispatch.sh` fast path, codex, one role → `OK` envelope, no `--agent`.
2. `codex-session-driver.sh` one turn → settle lines in `driver.log` with rc 0, turn
   text rebuilt from NDJSON, `ROLE_RESULT=DONE`.
3. `claude-session-driver.sh` one turn on claude-agent-acp 0.60.0 → same.
4. `build_codex_config` with the sandbox keys → one `exec` still returns `OK`.
5. Replay failure. **The open question is answered: the error does reach the JSON
   stream under `--json-strict`.** acpx emits CLI errors as JSON-RPC error objects on
   stdout, not as plain stderr text — proven by running a failing command with and
   without `--json-strict` and getting byte-identical 286-byte JSON both times. So the
   substring match sees the message inside `.error.message`, and no fallback is needed.
   The three exact strings (`Failed to replay saved session {model,mode,config option}`)
   are present in the installed 0.13.2 bundle, and the code path is a `throw` from
   `replayDesiredMode` and its siblings when acpx replaces a dead ACP session with a
   fresh one and re-applies the saved settings.

   Not reproduced end to end: forcing that condition needs a saved setting that is valid
   when written and rejected at replay, which means swapping the adapter under a live
   session. Corrupting `session_options.model` instead takes the `session/new` path and
   yields `model_not_found`, a different error. The fixture
   `tests/fixtures/acpx-envelope/replay-failure.ndjson` models the proven shape (a
   JSON-RPC error object carrying the message), and the driver tests assert the reason
   line is classified `errored` before the not-done fallthrough.

## Found while proving this, not fixed here

The codex **fast path never handled the `^BLOCKED:` sentinel**. It scans for
`NEEDS_DECISION:`, then falls through to the unparseable-envelope guard, so a fast-path
role that replies `BLOCKED: <reason>` is reported as
`ERRORED_REASON=unparseable_envelope` and its reason is lost. The comment above the
block names both sentinels as frozen, but only one is implemented. This is pre-existing
— `git show main` has the same shape — and it is unrelated to the six changes here, so
it stays out of this PR. Observed live: `plan-simulator` dispatched with empty inputs
replied `BLOCKED: No plan content/path or findings output path was supplied` and the
dispatch reported `unparseable_envelope`.

## Not doing

- `--append-system-prompt` for the preamble (claude-only; asymmetry across engines).
- `--no-fs` (moves file I/O, does not change safety; benchmark first, separate PR).
- `--prompt-retries` (a second retry loop under `delegate-leaf`'s own hides failures).
- `pool` and `zeroclaw` engines.
- Windows `agents.<name>.argv` migration.
- Bracketed model ids on `exec` (acpx rejects them; fact 4).
- A read-only substrate control for critic roles. The user chose the widest grant; the
  role body remains the only read-only guard, and `presets.yaml` says so.
